This is an R1 development-tooling adoption: local policy, commands, installed-contract tests and installation in the existing manual CI path.
It does not introduce a new trusted-candidate workflow, change CI triggers or permissions, or alter the JSON runtime contract.
No copied selector, checker, observer, staging engine or global fallback is needed.
Markdown Quality owns all Markdown checking and formatting; Prettier retains code and workflow formatting.

## Implementation slices

1. Pack the clean latest producer through its maintained packer, retain core and both native archives, and record full source/tree/lock and SHA-256/SHA-512 identities.
2. Install the archive-bound dev dependency through an isolated native npm lock with lifecycle scripts disabled; the archive filename includes the full source commit.
3. Add schema 2 root policy selecting all authored Markdown, preserve finite producer defaults, and provide root install/check/format/inspect commands.
4. Check the original corpus, repair demonstrated markup or local-link defects, then apply guarded formatting while preserving literal content and historical claims.
5. Exercise actual installed public contracts: independent Git inventory, ignored/untracked documents, missing non-Markdown targets, explicit command scope, excluded-byte preservation, and read-only checking.
6. Run affected repository verification, code/JSON/Markdown gates and native package-membership checks; retain findings and scope in external evidence.

## Acceptance and boundaries

Every tracked authored Markdown document is accounted for by the producer selector.
No historical plan, evidence document or agent instruction is excluded merely to obtain a pass.
External ignore files cannot suppress the Markdown policy.
Read-only checking reports genuine missing local targets and never changes document bytes.
Explicit file arguments retain explicit scope.
Source provenance, core/native archives and the isolated lock agree on the exact producer revision and bytes.
Native package membership excludes tooling, archives and integration tests from JSON Quality's shipment.
The existing manual CI producer setup installs this same graph before running its checks.

The producer's complete Windows/Linux trusted qualification workflow remains available for a separately frozen, committed bootstrap and candidate.
Its six-sample timing, process-memory and trust receipts are distinct from ordinary local checks; this local adoption does not claim those observations or copy another consumer's limits.
The existing clean-commit requirement for transported JSON package qualification remains in force.
The initial adoption request was local; the subsequent user instruction authorizes one detailed signed commit and direct publication to remote `main`.
Hosted workflow dispatch and release remain outside that publication scope.

Rollback restores the package/lock, policy, command, CI-install and document preimages together.
An installation downgrade alone cannot recover formatted documents.
Reassess on changed source/native identity, unexpected shipped files, literal changes, missing selection coverage or new public/trust requirements.
