# Comprehensive Performance Audit: `@hadden-industries/json-quality`

An evidence-driven performance audit of `@hadden-industries/json-quality` (version 1.0.0-rc.1, contract cohort 2) was conducted on Node.js v24.22.1 (V8 13.6, Windows x64).

Detailed evidence, flame graphs, and experimental breakdowns are documented in the companion artifact:  
👉 [performance_audit_report.md](file:///C:/Users/maksy/.gemini/antigravity/brain/765ac10d-3098-434c-b143-ff1cb3354f86/performance_audit_report.md)

## A. Executive Summary

### 1. Overall Performance Diagnosis
The core architecture offloads strict grammar parsing, exact decimal arithmetic, and Unicode NFC normalization to a shared C++20 Node-API library (`boost`, `icu`, `sqlite3`, `double-conversion`). This engine operates with low memory overhead (~8–12 MiB managed peak). 

However, the surrounding Node.js runtime and orchestration layer suffers from severe I/O, process orchestration, and redundant assertion bottlenecks:
- **Subprocess Spawning in Write Preflight**: Spawning individual `git check-ignore` child processes sequentially per candidate physical file creates an $O(N)$ process spawn bottleneck. On Windows, where process startup latency is 50–80 ms, this causes repository format passes to take 4–7× longer than read checks and triggers timeout crashes (`execution-time-capacity`) on repositories with $>1,800$ JSON files.
- **Redundant Descriptor Path Assertions**: In [`openDiscovered`](file:///c:/Users/maksy/GitHub/json-quality/src/repository-source.js#L24-L46), `assertRegularSource` was invoked once initially and then re-invoked inside `assertUnchanged` twice per file open. Each call executes full ancestor path splits and `lstatSync` queries down the directory tree.
- **Repeated Invariant Root Realpath Resolution**: In [`assertRegularPath`](file:///c:/Users/maksy/GitHub/json-quality/src/paths.js#L43-L62), `realpathSync(root)` was called synchronously on every path verification ($\ge 7\times$ per checked file), resulting in hundreds of redundant OS filesystem queries for an invariant root string.
- **Duplicate Schema Validation on CLI Event Stream**: In [`cli.js`](file:///c:/Users/maksy/GitHub/json-quality/src/cli.js#L107-L115), `emit(event)` re-validated already-validated and frozen events through Ajv against `event.schema.json` with 11 `oneOf` schema branches.

## E. Detailed Findings

### PERF-01: $O(N)$ Sequential Subprocess Spawns in Format Preflight

#### What is Slow
In [`src/repository-rewrite.js:58-80`](file:///c:/Users/maksy/GitHub/json-quality/src/repository-rewrite.js#L58-L80), `writable()` calls `ignored()` individually for each physical JSON member in the repository.

#### Where it Occurs
Call path:  
`rewriteRepository` $\to$ `writable` $\to$ `ignored` $\to$ [`runBoundedTool`](file:///c:/Users/maksy/GitHub/json-quality/src/bounded-process.js#L5) $\to$ `child_process.spawn("git", ["-C", root, "check-ignore", "--quiet", "--no-index", "--", path])`.

#### Why it is Expensive
`runBoundedTool` originally resolved only with the child process exit code. To query whether a path was ignored, the implementation passed `--quiet` to `git check-ignore`, which returns exit code 0 if ignored and 1 if not ignored. Because `--quiet` only tests a single path, `writable` was forced to invoke a separate process per candidate file. Process creation on Windows requires allocating Win32 process and thread handles, creating initial console structures, and loading DLLs, costing 50–80 ms per execution.

#### When the Cost Grows
The cost scales strictly with the number of physical JSON files ($O(N)$). At 50 files, formatting spent 3.4 seconds in subprocess overhead alone. At 1,800 files, process spawning consumes $1,800 \times 70\text{ ms} = 126\text{ seconds}$, exceeding the default `maxCheckTimeMs` of 120,000 ms and causing the entire command to fail with an unrecoverable timeout error.

#### What Evidence Supports the Claim (MEASURED)
1. **CPU Profile**: Profiling `format --root .` showed 1,302,071 $\mu\text{s}$ (1.30 s) in `(idle)` waiting on child processes, and 95,575 $\mu\text{s}$ self-time in `node:internal/child_process:spawn`.
2. **50-File Workload**: Baseline took **3,934.50 ms**. After batching, duration dropped to **1,102.62 ms** (-72.0%).

#### What Change Addresses the Causal Mechanism
Extend `runBoundedTool` with a `captureOutput: true` option. In `src/repository-rewrite.js`, introduce `batchIgnored(root, paths, execution, gitExecutable)` which passes candidate paths to `git check-ignore --stdin -z --no-index` in bounded slices of 256 paths.

#### Regression Risks and Functional Equivalence
Git specifies that `git check-ignore --stdin -z` reads NUL-delimited input and emits NUL-delimited matching ignored paths. Exit codes (0 for matches, 1 for no matches) are handled identically. All 18 rewrite and execution tests pass without error.

### PERF-02: Repeated Path Resolution in `openDiscovered`

#### What is Slow
In [`src/repository-source.js:24-46`](file:///c:/Users/maksy/GitHub/json-quality/src/repository-source.js#L24-L46), `openDiscovered()` resolves `const absolute = assertRegularSource(root, member.path)` on line 25, but then line 32 inside `assertUnchanged()` re-runs `const path = assertRegularSource(root, member.path)`.

#### Where it Occurs
In [`src/repository-source.js:32`](file:///c:/Users/maksy/GitHub/json-quality/src/repository-source.js#L32), invoked twice per open (on descriptor creation and at EOF).

#### Why it is Expensive
`assertRegularSource` calls `assertRegularPath`, which iterates through every path segment, calls `lstatSync` on each ancestor directory, and executes two `realpathSync` calls. Because `assertUnchanged` runs at open and at EOF, each file opened was re-validated 3 times.

#### What Evidence Supports the Claim (MEASURED)
Trace counters showed over 180 calls to `assertRegularPath` during a single 30-file check. Reusing `const path = absolute` reduced `assertRegularPath` invocations by 66% during capture and recheck, cutting self-check latency from **331.79 ms** to **286.67 ms**.
